# Performance hot paths (round 2) + correctness evals — roadmap

## Context

Prior optimization passes already landed the obvious architecture (private-framework bridges, IndigoHID input, IOSurface screenshots, in-process caches). This roadmap is a deeper pass on the remaining hot paths, plus "benchmarking" in the LLM-evals sense — correctness evaluation, not just hyperfine latency. Tracking stays lightweight: local JSONL/markdown, no hosted experiment tracking. Implementation and verification require a Mac with Xcode and a booted simulator.

A fuller per-item design (function signatures, spike steps, check-by-check details) lives in [perf-and-evals-design.md](perf-and-evals-design.md).

## Findings (verified first-hand in code)

1. **The AX tree walk is an XPC storm — the dominant remaining cost.** `serializeElement` (Sources/SimulatorKit/Accessibility/AXPAccessibilityBridge.swift:365) fetches ~9 properties per element (role/label/title/value/identifier/help/frame/traits/children); each lazy `AXPMacPlatformElement` accessor goes through the token delegate → `sendAccessibilityRequest` → blocking `DispatchGroup` wait (Sources/SimulatorKit/Input/PrivateFrameworkBridge.swift:530), strictly serial. 200 elements ≈ ~1,800 XPC round-trips. A fresh `DispatchQueue` is allocated per call (line 543).
2. **Every selector op pays the full storm.** `resolveSelector` (Sources/iosef/Schemas.swift:35) walks the entire tree with full projection even for `exists` (needs first match) and `tap`-by-selector (needs frame of first match only). `wait` re-fetches the full tree every 250ms (Sources/iosef/ToolHandlers.swift:241).
3. **Timing constants are unmeasured guesses:** 30ms tap hold, 10ms/char typing, 100ms keyboard settle, 10ms swipe step, 250ms wait poll (IndigoHIDClient.swift:42,118,68; ToolHandlers.swift:60,257). MCPTestApp's `tap_count_label` / `text_field` / `swipe_status_label` are ready-made ground-truth oracles for calibrating them.
4. **`typeText` is ASCII-only and O(n) HID round-trips** — non-ASCII silently dropped (IndigoHIDClient.swift:107). A correctness bug and a perf ceiling at once.
5. **Every CLI invocation spawns `jj root` (+ `git rev-parse`)** via `setupGlobals()` → `computeDefaultDeviceName()` (Sources/iosef/CLICommands.swift:47-59) — even with explicit `--device`.
6. **Eval infrastructure is latency-only.** `scripts/benchmark.py` = hyperfine wall-clock, mean-based, /tmp-ephemeral. `skills/ios-simulator-interaction-workspace/evals/evals.json` has 5 behavioral eval rubrics but **no runner**. No correctness suite, no committed baselines, no CI tests.

## Research verdicts (with sources — see design doc for links)

- **Bulk attribute fetch is real (the big lever).** Decompiled `AccessibilityPlatformTranslation` (iOS 17.6/26.1 restores + iOS 18.2 dyld-cache headers) shows the XPC protocol iosef already speaks has `processTranslatorRequest:` types **1**=applicationObject, **2**=attribute, **4**=frontMostApp, **5**=**multipleAttribute**, **6**=hitTest, … . `processMultipleAttributeRequest:` takes `parameters[@"attributes"]` (array of attribute codes) and services them with **one** `AXUIElementCopyMultipleAttributeValues` call. iosef can construct `AXPTranslatorRequest` objects directly and send them through the existing `sendAccessibilityRequest(_:toDevice:)` — bypassing the lazy accessors: **~9 XPC/element → 1**. Because direct requests never touch the AXPTranslator singleton or token delegate, pipelining sibling fetches concurrently becomes purely our code — the translator thread-safety question evaporates.
- **Dead ends, cut:** xctree uses the public macOS AX API (requires Accessibility permission — violates iosef's zero-permission design); WDA/XCTest `snapshotWithAttributes` needs an XCUITest runner + testmanagerd session with documented timeout problems on large trees; concurrent walks *through* the translator singleton (mutable caches, token-pinning hazard noted by SimPilot).
- **Pasteboard paste is validated by precedent:** lycorp-jp/sim-use ships `simctl pbcopy` + HID Cmd-V (0xE3 down, 0x19 down/up, 0xE3 up). Caveats: requires hardware-keyboard mode; soft-keyboard-only drops Cmd-V (edit-menu long-press "Paste" is the documented fallback — don't build until needed); one known Xcode 26.4 paste regression (fixed 26.5).
- **Bar to beat:** testa (closest competitor) uses the same per-attribute AXP pattern with a warm daemon at ~60ms/snapshot.
- iOS 18+ has a **tree-dump cache** (`requestResolvingBehavior`, `handleUpdatedAXTree:`) — a true one-push whole-tree path, but needs a host notification channel iosef hasn't plumbed. Deferred spike, only if bulk+pipelined isn't enough.

## Roadmap (priority order)

|---|------|--------|--------|
| 1 | **E4 — perf instrumentation.** `IOSEF_PERF=1` → one JSON line on stderr per op: `{"iosef_perf":{"op":"describe","xpc_ax":…,"xpc_hid":…,"hit_tests":…,"elements":…,"wall_ms":…}}`. New `Sources/SimulatorKit/PerfStats.swift` (NSLock-guarded counters); hook `sendAccessibilityRequest`, `sendMessage`, `hitTestNode`; emit from the `handleToolCall` wrapper. | S | Makes "XPC calls per op" a first-class regression metric — measurement before optimization. |
| 2 | **E1 — deterministic correctness suite.** New `scripts/correctness.py` (uv/click, benchmark.py conventions). 9 oracle checks against MCPTestApp: all 48 `grid_R_C` in describe with sane frames; tap ×3 → `tap_count_label`=="3"; ASCII type readback + `[MCPTest] Text changed` log; **non-ASCII type (xfail today)**; swipe → `swipe_status_label` direction; issue-#2 navbar regression; point-describe; wait fast-path latency; `--watch` variant. Each check timed and run with `IOSEF_PERF=1`. Output `results/*.jsonl` + `summary.md`; `--baseline` (correctness regressions fail, latency >25% warns, `--strict-latency` fails); `--update-baseline` writes gitignored per-machine baseline; committed structural expectations in `scripts/expectations/mcptestapp.json`. | M | The guardrail every perf change below is gated on; doubles as the latency+XPC trend tracker (lightweight, local files). |
| 3 | **P6 — micro wins.** (a) shared static callback queue in `sendAccessibilityRequest` (PrivateFrameworkBridge.swift:543); (b) lazy memoized `defaultDeviceNameProvider` so `jj`/`git` spawn only when no explicit device/session/cache (CLICommands.swift:58); (c) push `describe --depth` into the walk instead of fetching everything then truncating in TreeSerializer (ToolHandlers.swift:39); (d) env-gated swipe fire-and-forget (block only on final up message), `IOSEF_SWIPE_PIPELINE=1` until E1's swipe check proves it. | S | Free wins, zero protocol risk. |
| 4 | **P1 — selector-aware traversal.** New `TraversalPlan` (projection `.full`/`.selectorMatch`, `selector`, `stopAfterFirstMatch`, `maxDepth`, `expandEmptyContainers`); `accessibilityElements(plan:)`. Under `.selectorMatch` fetch only the 4 attrs `AXSelector.matches` reads; on match fetch the rest for that node only (frame transformed via existing `cachedRootFrame`); early-exit via sentinel error. Skip hit-test expansion unless zero matches → then one fallback full walk (preserves issue #2 selectors on the slow path). `resolveSelector(firstMatchOnly:)`: exists/text/tap/type/wait → first-match; count/find → projected full scan. | M | `exists` hitting element #30 of 200: ~1,800 → ~130 XPC. `wait` polls get the same cut. No wire-protocol risk. |
| 5 | **P2a — direct multi-attribute request engine.** Mac spike first (1-2 days): log `request.description` through the existing dispatcher to learn attribute codes; hand-build requestType 5 (and 4/6) and decode `response.resultData` (frame encoding, children translation objects, coordinate space). Risks: attribute-code renumbering across OS versions (runtime name assertion + legacy fallback), per-kind value decoding (E1 covers field/toggle/slider/buttons). |
| 6 | **P5 — pasteboard type fast-path.** `IndigoHIDClient.pasteChord()`; `handleType` auto-pastes for non-ASCII or ≥20 chars (`IOSEF_TYPE_MODE=auto\|keys\|paste`, CLI/MCP override); `simctl pbcopy <udid>` with stdin (needs stdin-capable `SimCtlClient.run` variant); calibrated settle. In `keys` mode, unsupported chars become an explicit error instead of silent drops. | S/M | O(1) typing for long text + fixes the non-ASCII correctness bug (flips E1's xfail). |
| 7 | **P4 — timing calibration.** Replace magic constants with env-tunable `Tunables` (`IOSEF_TAP_HOLD_MS`, `IOSEF_KEY_DELAY_MS`, `IOSEF_KEYBOARD_SETTLE_MS`, `IOSEF_SWIPE_STEP_DELAY_MS`, `IOSEF_WAIT_POLL_MS`, `IOSEF_PASTE_SETTLE_MS`). `scripts/calibrate.py`: per constant, binary-search the smallest value passing 20/20 oracle trials, ×1.5 margin; suggested defaults reviewed and committed manually (machine-dependent). Shared sim/oracle helpers extracted to `scripts/_iosef_harness.py` (used by correctness.py too). | M | Turns guessed sleeps into measured ones — likely reclaims tens of ms per tap/type. |
| 8 | **E3 — token-efficiency metrics.** `benchmark.py tokens` mode: describe output size (bytes + ~tokens) for iosef md/json vs `idb ui describe-all` vs node ios-simulator-mcp on a fixed MCPTestApp screen; results alongside E1's. | S | Completes the "agent cost" axis — verbosity regressions become visible. |
| 9 | **E2 — agent-eval runner.** `skills/ios-simulator-interaction-workspace/evals/run_evals.py`: per evals.json case — reset sim/app, `claude -p "<prompt>" --output-format stream-json --max-turns 30` with the skill, grade two-layer: programmatic app-state checks (tap_count, log line, swipe label) + transcript greps (no `--help`, selector flags used), then an LLM judge returning strict JSON per expectation. Emit `iteration-N/` dirs (gitignore already anticipates), `results.jsonl` (success, expectation ratio, tool calls, tokens, wall time) + `summary.md`; `--case`, `--iterations`. | M/L | LLM-evals-style correctness benchmarking on the existing 5 rubrics. |

**Deferred:** P2b tree-dump cache (only if direct+pipelined describe still >300ms on big trees); P7 CLI daemon (unix socket reusing `handleToolCall`, spawn-on-demand, build-hash handshake — MCP mode already amortizes; testa's ~60ms shows the ceiling). **Cut:** concurrent walks through the translator singleton; XCTest/WDA stack; xctree's public-AX approach; any hosted tracking.

## Verification

1. Land E4+E1 first; capture a baseline (`correctness.py --update-baseline`) including per-op XPC counts.
2. Every subsequent change: `correctness.py --baseline` green (incl. navbar regression + watch variant) + `benchmark.py` current-vs-baseline for describe/tap/exists/wait.
3. P2a parity gate: E1 under `IOSEF_AX_ENGINE=legacy` vs `direct`, diff full describe trees (float-tolerant frames).
4. P5 gate: `type_nonascii` flips xfail→pass; long-string type latency drops.
5. Pure-logic unit tests for TraversalPlan matching/early-exit (no simulator needed), modeled on HitTestChildDiscoveryTests.
6. Per CLAUDE.md, after interface changes review: skills/ios-simulator-interaction, scripts/benchmark.py, README.md.
